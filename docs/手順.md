# 実行手順・設定条件（詳細）

「町田駅から徒歩10分で行ける範囲は、半径800mの円とどれくらい違うのか？」を QGIS + QuickOSM + QNEAT3 で調べる。

## 環境（2026-10-12 セットアップ・確認済み）

| 項目 | バージョン | 備考 |
|---|---|---|
| QGIS | 3.40.5（`/Applications/QGIS-LTR.app`） | 現行LTRは3.44。QNEAT3は3.x専用なので QGIS 4 には上げない |
| QuickOSM | 2.5.4（2.4.1から更新。旧版はバックアップ済み） | plugins.qgis.org 公式版 |
| QNEAT3 | 1.0.8 | plugins.qgis.org 公式版。開発終了（後継 QNEAT 4.0 は QGIS 4 専用） |
| matplotlib（QGIS同梱） | 3.3.0 | QNEAT3 の Polygons/Contours には古すぎる（下記） |

### 分かった制約と対応

- **QNEAT3 の「Iso-Area as Polygons / Contours」は、この環境では失敗する。**
  `AttributeError: 'QuadContourSet' object has no attribute 'get_paths'`（matplotlib 3.8 以降の機能を使っているため）。
  → **QNEAT3「Iso-Area as Interpolation (from Layer)」で到達コストのラスタを作り、GDAL「等値線（ポリゴン）」で面にする。** QGISの画面で操作するときも同じ手順にする。
  - そのとき Interpolation の「Size of Iso-Area」は **到達コストの1.1倍（10分なら880）** にする。QNEAT3 の Polygons アルゴリズムも内部で同じことをしている（`IsoAreaAsPolygonsFromLayer.py` の `calcIsoPoints(..., max_dist+(max_dist*0.1))`）。800 のままだと、800m の等値線が点群の外枠になり、到達圏が四角く切れる。
- QuickOSM 2.5.4 は、出力ファイル名の末尾5文字を削って GeoPackage として保存する（`.gpkg` を前提にしている）。そのため保存先は `.gpkg` で指定する。
- QuickOSM の出力は、タグが1列ずつに展開されている。また OSM の `distance` タグと同じ名前の列があるので、接続距離は別の名前の列（`snap_m`）で計算する。
- QNEAT3 1.0.8 の Entry Cost は「Planar」しか選べない → ネットワークは必ず投影座標系（EPSG:6677）で渡す。
- `qgis_process` を直接呼ぶと proj.db と osmconf.ini が見つからない → `scripts/qp.sh` で環境変数を設定して呼ぶ。

## 自分でやること：起点を置く

1. QGIS で `data/origin.gpkg` の `origin` レイヤ（EPSG:6677、空）を開く。
2. JR東日本の駅構内図・地理院地図・OSM を見て、JR町田駅 北口側の地上出入口に **点を1つ** 置く。
3. 属性を入力する：`name`（出入口名）、`exit_type`（地上／デッキ等）、`note`（選んだ理由）、`checked_on`（YYYY-MM-DD）、`source`（確認した資料）。
4. 保存する。

## 実行

```bash
cd machida-walk
/Applications/QGIS-LTR.app/Contents/MacOS/bin/python3 scripts/run_minimal.py
```

- 初回は QuickOSM で Overpass API から道路を取得し、`data/osm_highway_日時.osm` に保存する。
- 2回目以降は `--osm-file data/osm_highway_日時.osm` を付けると、同じデータで再計算する（結果を再現するため）。
- 出力は `output/run_日時/`、設定・バージョン・各処理の入出力は `logs/run_日時.json` に残る。

## 処理の流れ（GUI での対応操作）

| # | 処理 | アルゴリズム | GUI での場所 |
|---|---|---|---|
| 1 | 起点を EPSG:6677 に変換し、ID を付ける | native:reprojectlayer, fieldcalculator | プロセシング → ベクタ一般 |
| 2 | 起点から 2,000m の範囲で `highway` を取得 | quickosm:downloadosmdataextentquery | QuickOSM（キー highway・レイヤの領域） |
| 3 | EPSG:6677 へ変換 → 歩けない道を除外 | reprojectlayer, extractbyexpression | 式による抽出（式は log の `walkable_expression`） |
| 3b | 道の途中に10mおきに頂点を追加（新しい接続は作らない） | native:densifygeometriesgivenaninterval | 間隔を指定して高密度化 |
| 4 | 起点から最寄りの歩行可能な道までの距離 | native:shortestline | 地物間の最短ライン |
| 5 | 到達コスト（Shortest＝距離、両方向、許容値0。点群は800m、補間は880m） | qneat3:isoareaaspointcloudfromlayer, isoareaasinterpolationfromlayer | QNEAT3 → Iso-Areas |
| 5b | 800m の等値線ポリゴン → 融合 | gdal:contour_polygon, native:dissolve | GDAL → ラスタ抽出 → 等値線（ポリゴン） |
| 6 | 半径800m の円（1/4円あたり32分割） | native:buffer | バッファ |
| 7 | 円−到達圏、到達圏−円、各面積 | native:difference, exportaddgeometrycolumns | 差分、ジオメトリ属性を追加 |

## 設定条件（レポートに書くこと）

- 時間の扱い：**一定速度で距離から換算**。80 m/分 × 10 分 = 800 m を Shortest（距離）で計算。信号待ち・坂・階段・混雑は含めない。
- 方向：両方向。OSM の `oneway` は車向けなので使わない。
- トポロジー許容値 0：線は共有する頂点でだけつながる。OSM で頂点を共有しない橋や地下道は、下の道とつながらない。
- 除外する道：highway が motorway / motorway_link / construction / proposed / raceway / bus_guideway / abandoned / razed / platform のもの、`foot=no|private`、`access=no|private`（ただし `foot=yes|designated|permissive` があれば残す）。
- 到達圏ポリゴンは、頂点のコストを補間した推定の面。内部のすべての地点に歩いて行けるとは限らない。

## 動作確認（合成データ・ネットワーク接続なし）

`tests/make_synthetic_osm.py` で作った架空の100m格子（実在の道ではない）で確認した。北側に「線路」があり、通れるのは歩道橋1か所だけ。高速道路と `foot=no` の近道も入れてある。

- 高速道路と `foot=no` の道は `excluded_ways` に入った。
- 到達圏は起点の北195mで止まり、北へ越えたのは歩道橋の付近だけだった。
- 円の面積は 2,009,812 m²（π×800² = 2,010,619 m² に対して −0.04%）。
- 到達圏の面積：頂点を足さない場合は 701,415 m²、10mおきに足した場合は 846,926 m²（どちらも補間の上限は800m）。後者のほうが手計算の見積もり（約80万m²）に近いので、10mおきを既定にした。
- 補間の上限を1.1倍（880m）にしたあとの面積は 891,375 m²。切れ目の手前の帯まで含めた見積もり（約86万m²）より、約4%大きい。点の間を補間するので、切れ目の付近では面が少しはみ出す。
